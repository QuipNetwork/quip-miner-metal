How this was measured

  • Probe: crates/ane-miner/probes/utilization.m, which builds the production sweep text with the read layout and the weight encoding lifted out, and bare 1×1 convolutions for the ceilings.
  • Each point is the fastest clean window over three rounds. A window is contaminated by another client's program creation in the aned log (5-second lead included), by ANE power above 0.05 W in the idle gap before it, or by GPU power above 1 W inside it. Rounds and clean rounds are shown in the table.
  • Fresh compiles of one program vary by about 15%: six sparse compiles at 128 reads ran 0.42–0.52 ms, six fp16 compiles 0.64–0.78 ms. The two sparse points at 64 and 128 reads come from the concurrency grid's single-process launches, the cleanest runs of those points.
  • Power: macmon at 250 ms, samples inside each timing window, first sample dropped. ANE power idles at 0 W.
  • Every encoding and layout at a given read count hashes to the same output surface, so the speed differences carry no change in results.
  • Rates are dispatch cost only; the production path adds threshold staging per sweep.
